## 0. 촬영 전 준비 (녹화 시작 전)

### 0-1. 환경
```bash
cd ~/Downloads/devops_todo/FastApi_Todos
ollama serve                 # Ollama로 찍을 때 (Gemini면 .env의 LLM_PROVIDER=gemini 확인)
./scripts/reset-demo.sh      # 메트릭·로그·인시던트 기록·Todo 데이터 초기화
```
- 리셋 후 **2분** 기다린다 (정상 상태 그래프가 쌓이도록)
- KPI 화면(장면 9)을 채우려면 리셋 뒤 **리허설 2~3회**를 돌려 둔다. 리허설도 실제 실행이라 통계에 포함된다.
  리허설 사이에는 3~5분 간격을 둔다 (이전 장애 로그가 증거에 섞이지 않도록).
- 리허설로 생긴 Discord 메시지는 지우거나, 녹화용 채널을 따로 만든다.

### 0-2. 브라우저 탭 (순서대로 열어 두기)

### 0-3. 화면 정리

🎙 (LLM 설명 한 줄)
> "LLM은 로컬 Ollama의 qwen3 8B를 기본으로 쓰고, 환경변수 하나로 Gemini로 바꿀 수 있게 했습니다."

## 장면 5. 에이전트 조사 (5:30 ~ 7:00) ★ 핵심 장면

🎬 ⑤ Discord — `🚨 TodoHighErrorRate 알림 수신 — AI 에이전트가 조사를 시작합니다.` 메시지와 스레드 생성

🎙
> "알림이 오자마자 에이전트가 인시던트를 열고 스레드를 만들었습니다."

🎬 스레드를 열어 진행 메시지가 하나씩 올라오는 것을 보여줌
- `📊 기본 증거 수집: 핵심 지표 · 에러/지연 로그 · 최근 설정 변경`
- `🔧 query_prometheus_range …` / `🔧 search_logs …` / `🔧 get_runtime_config`
- `💬 (중간 결론)` → `🧠 보고서 작성 중…`

🎙
> "평소 사람이 하던 일을 떠올려 보시면, 알림을 받고, 대시보드를 열고, 로그를 검색하고, 최근에 뭐가 바뀌었는지 확인합니다.
> 에이전트는 이 과정을 도구 호출로 수행합니다.
> 먼저 지표·로그·최근 설정 변경 같은 기본 증거를 **결정적으로** 모으고,
> 그다음 LLM이 필요한 도구를 스스로 골라 추가로 확인합니다.
> 여기 보이는 게 PromQL로 언제부터 나빠졌는지 보고, Loki에서 에러 로그를 찾고, 런타임 설정을 확인하는 과정입니다."

✂️ 알림 → 보고까지 약 1~2분 → 도구 호출이 올라오는 부분만 남기고 컷

> ⚠️ Gemini는 기본 증거만으로 결론을 내 도구 호출이 0~1회일 때가 있다. 도구 호출 장면이 중요하면 Ollama로 찍거나, 리허설에서 호출 횟수를 확인한다.

## 부록 B. 촬영 중 문제가 생기면
| 상황 | 대처 |
|---|---|
| 알림이 1분 넘게 안 뜸 | ③ /alerts에서 Pending인지 확인. 에러율 50%면 보통 45초 안에 Firing |
| 보고서 footer에 `⚠️ LLM 실패` | Ollama 실행 확인 후 `/chaos off` → 3~5분 뒤 다시 시작 |
| 보고서 근거에 엉뚱한 로그 | 이전 장애와 간격이 짧았던 것. 3~5분 쉬고 재촬영 |
| 버튼이 "인시던트를 찾을 수 없음" | 에이전트가 재시작된 것. 새로 장애 주입 |
| 다시 처음부터 | `/chaos off` → `./scripts/reset-demo.sh` → 2분 대기 |
